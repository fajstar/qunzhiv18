隐私保证

这份页面只讲一件事：你的论文正文去哪了。结论是——它没有离开你的浏览器，除非你主动把它发给你自己的 LLM 服务商。

你的论文正文永远不会离开你的浏览器。

规则检查：纯 JS 在本地跑。深度评审：你的浏览器直连 LLM 服务商（key 是你自己的）。我们只收到：特征名、文献标题、论文 id。我们收不到：正文、摘要、作者、邮箱。

一、数据流：三种模式，三条边界

纯本地 20 项规则 + T1/T2/T3 锚定。只加载本目录的 HTML/CSS/JS，0 个业务请求。断网照常工作。
本地 + 云端公开统计 只调用 5 个 /api/pub/* 接口。请求体里只有特征名、领域、文献标题、pid、关键词。
本地 + 你自己的 LLM 浏览器直连你配置的服务商。正文只发往那一家；qunzhi.team 连请求都看不到。

二、我们收到什么 / 收不到什么

数据是否离开浏览器说明
论文正文 / 全文否（除非你开 LLM）只存在于页面内存与文本框；刷新/关闭即消失。
摘要否规则和锚定都在本地跑，摘要不单独发送。
作者 / 邮箱 / 单位否接口字段白名单里没有这些字段；传了会被 400 拒绝。
特征名（如 seed / ci）是（开云端时）用于查同行缺失率，例如 {"feat":"seed","field":"cs.LG"}。
文献标题是（开云端时）公开信息；用于漏引分析，最多 50 条。
论文 id / 关键词是（开云端时）查 benchmark / 公开检索。
LLM key否只存在你本机的 localStorage；请求头直接发给 LLM 服务商。

三、自己抓包验证（最关键的一节）

不要相信任何口头承诺。按下面步骤，你能在 2 分钟内自己验证。

1
打开 DevTools → Network

Chrome / Edge 按 F12，或右键「检查」。勾选 Preserve log，清空现有记录。

2
关闭「云端公开统计」，粘贴正文，点「开始检查」

纯本地模式。Network 面板里应当只有本目录的静态资源（HTML/CSS/JS），没有任何 qunzhi.team 请求，也没有任何 LLM 请求。

3
再打开「云端公开统计」，重新检查

这时只会出现 https://qunzhi.team:8443/api/pub/baseline 与 /api/pub/missing_cites。点开请求 → Payload，确认里面只有 feat / field / refs，没有正文。

4
配置你自己的 LLM，点「深度评审」

Network 里会出现一个指向你填的 base_url 的请求（例如 api.deepseek.com），请求体里有正文；没有任何请求发往 qunzhi.team 携带正文。请求头的 Authorization 是你自己的 key，我们看不到。

5
断网测试

关掉 Wi-Fi / 拔网线，刷新页面，点「载入示例 → 开始检查」。20 项规则与锚定照常出结果。这证明规则不依赖服务器。

云端请求长什么样（真实字段，已脱敏）

POST /api/pub/baseline
{"feat": "seed", "field": "cs.LG"}

POST /api/pub/missing_cites
{"refs": ["Deep Residual Learning for Image Recognition",
          "Attention Is All You Need"],
 "field": "cs.CV", "siblings": 30}

GET /api/pub/benchmark?pid=ax_2611.26510
GET /api/pub/search?q=attention&limit=10
GET /api/pub/version

如果你在这些请求体里看到 text、abstract、author、email，那是我们的 bug，请立刻停止使用并提 issue。服务端对这些字段是硬拒绝（HTTP 400），不是「忽略」。

页面内的网络计数器

检查页右上角有一个「本次检查 N 个请求」的小标签，设置弹窗里还有完整列表（只记 URL / 方法 / 状态码，不记请求体）。每次点「开始检查」会清零重计。它是给你做交叉验证用的，不是唯一证据——以 DevTools 为准。

四、源码可审

整个工具是纯静态 HTML/CSS/JS，没有构建步骤、没有压缩混淆、没有第三方 CDN。你可以直接读每一行：

  • static/rules.js：20 项规则的正则、为什么重要、怎么补。
  • static/anchor.js：T1/T2/T3 锚定、参考文献解析。
  • static/qz.js：所有交互与网络请求；搜索 fetch( 就能看到全部出口。
  • config.js：默认配置；file:// 下连 config.json 都不请求。

源码仓库：github.com/qunzhi-team/qunzhi-local。如果链接暂时 404，说明仓库还没发布；本包内的源码与仓库一致，可直接审计本地文件。

五、边界与诚实说明

「正文不上传」有前提，我们不想含糊：

  • LLM 模式例外：你主动点「深度评审」并确认后，正文会发给你配置的 LLM 服务商。它是否会留存、用于训练，取决于那家服务商的条款，不取决于我们。不想发就别开 LLM。
  • 浏览器扩展：如果你装了会读取页面内容的扩展，它理论上能看到文本框。请用干净的浏览器配置。
  • HTTPS 终止：云端接口走 HTTPS；证书由部署方维护。若你看到证书警告，先别继续，核对证书再使用。
  • 服务器访问日志：云端可能记录 IP、时间、URL、状态码（运维必需），但不记录请求体中的论文内容——因为请求体里本来就没有正文。
  • 正则不是语义理解：规则只能发现「文中是否出现相关表述」，不能判断实验做得对不对。所有结论必须由人确认。
  • CORS：部分 LLM 服务商不允许浏览器直连。失败时我们不会替你转发，只会提示你换服务商或使用本地 Ollama。

六、常见问题

为什么双击打开时不能自动读取 config.json？

浏览器的同源策略禁止 file:// 页面读取本地 JSON。纯本地模式不需要它；要用 config.json，请在本目录运行 python -m http.server 8000，再访问 http://localhost:8000/?config=1。默认不带参数时不读文件，避免 404。

key 存在哪？

只存在浏览器的 localStorage（键名 qz_local_settings_v1），不会写到文件、不会发给 qunzhi.team。公共电脑上用完请点「清除 key」。

云端统计的数据从哪来？

公开论文库的聚合统计（L1/L2 论文的特征分布、公开文献引用关系、公开 benchmark 数字）。接口不返回论文全文、摘要或作者。

你们能保证「绝对安全」吗？

不能，任何软件都不能。我们能保证的是：代码开源可审、请求字段有硬白名单、正文不进入云端代码路径、你可以用抓包和断网自己验证。剩下的风险（扩展、服务商条款、证书）已在上面列明。
