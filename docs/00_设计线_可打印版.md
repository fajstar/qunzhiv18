## 第 0 部分｜是什么：一句话说清

> **读者问**：群智 v18 到底是什么？
>
> **一句话回答**：它把一篇 PDF / LaTeX 论文，在 **40–80 秒**内变成一份 **16 条左右、每条都能点回原文**的问题清单。

它不写评审意见，也不替你改论文。它做的是：把论文里**能被原文核对**的毛病找出来，按严重度排好，每条附上原文、改法、验收标准，以及"什么情况下可以不改"。

为什么限定"能被原文核对"？因为这是作者唯一能**当场判断该不该信**的办法。

### 0.1 它做的事，四步

```text
[1] 上传：PDF / LaTeX / DOCX / 文本（正文 ≥500 字）
     │
[2] 提取：十类问题 + 六个易漏方向补漏 + 主张审计（逐条检查结论有没有证据）
     │
[3] 锚定：把每条问题和原文逐字对上，分 T1 / T2 / T3（逐字 / 部分 / 无依据；T3 直接拦掉）
     │
[4] 出清单：≤16 条（可调 8 / 20 / 24），每条 = 问题 + 原文 + 改法 + 验收 + 可忽略
```

**图 0-1　从论文到清单：四步，40–80 秒。** 先记住三个数：40–80 秒、16 条、99% 的候选能定位回原文（进清单的 100% 有锚点）。轻量模式会更快；本文统一按完整流程的 40–80 秒计。

### 0.2 清单长什么样

下面是一条示例（演示用，不是某篇真实论文的结论）：

| 栏目 | 内容 |
|---|---|
| 问题 | 未报告随机种子与搜索预算 |
| 原文锚点（问题对应的原文） | "without reporting the random seeds"（§3.2 即第 3.2 节，Implementation，第 14 行） |
| 为什么是问题 | 结果无法复现，审稿人一定会追问 |
| 怎么改 | 在 §3.2 补一句：随机种子、搜索预算、重复次数 |
| 验收标准 | 读者能按这句话复现出同一组结果 |
| 可忽略条件 | 若论文明确是工业级大规模训练、确实不可复现，可只说明这一限制 |

一条问题不是一句"我觉得"，而是**问题、证据、改法、验收、边界**五件事。

### 0.3 它不是什么

- **不是 AI 审稿人**：不写评审意见、不打分、不替会议做接收决定。
- **不是论文改写器**：不替你重写段落，只告诉你"改哪句、怎么验收"。
- **不是万能查错**：只对文字里能逐字核对的问题负责；图内数值、领域判断不包办（见第 5 部分）。

## 第 1 部分｜为什么：这解决什么问题？

> **读者问**：这解决什么问题？
>
> **一句话回答**：解决"AI 说得头头是道，作者却没法验证该不该信"的问题——我们让每条问题都带一段能点回原文的"收据"。

### 1.1 一个熟悉的场景

你用某个 AI 工具读论文，几十秒后拿到 20 条建议：语气专业、结构完整，甚至分了"重大 / 次要"。

但你逐条核对时，会遇到三类问题：

1. **引用对不上**：它说"论文没报告置信区间"，你翻回原文，发现附录里写了。
2. **数字找不到**：它建议"把样本量从 1 万加到 5 万"，但原文根本没有"1 万"这个数。
3. **建议放之四海皆准**：十条里有六条是"建议补充实验""建议加强对比"，不改也行，改了也不知道算不算改好。

于是作者的真实处境是：**不改怕漏，改了怕错，最后只能凭感觉挑几条。**

### 1.2 痛点和解法

审稿人给意见，作者至少知道"这是一个人对这篇论文的判断"；AI 给意见，作者面对的是黑箱：它读没读全文？引的那句在第几节？数字是原文的还是编的？**没有这些信息，建议越多，筛选成本越高。**

所以问题不是"AI 不够聪明"，而是"AI 的输出不可核验"。我们的解法是给每条问题配一张**收据**——也就是**锚点**：一段和原文逐字对得上的文字。作者点开锚点，3 秒就能判断"这条是真的还是假的"。

这张收据要能回答三件事：**在哪**（哪一节、哪一句）、**凭什么**（这段原文能不能支撑"这里有问题"）、**怎么改**（改哪句、怎么验收、什么情况下不用改）。

### 1.3 不做什么

定位是**作者自查**：不替你写评审、不替你改论文、不做"AI 审稿人"（不预测接收率、不打分、不排名）。需要领域共识的判断（约 51%）标"待确认"，不装懂（见第 5 部分）。

### 1.4 一张表看清差别

| 维度 | 普通 AI 审稿 / 查错工具 | 群智 v18 |
|---|---|---|
| 输出形态 | 一段段流畅的建议 | 一条条带编号的清单 |
| 依据 | 可能引用，但常对不上 | 每条带逐字锚点，可点回原文 |
| 你如何验证 | 回去自己找，找不到只能猜 | 点开锚点，几秒判断真假 |
| 谁做判定 | 生成建议的模型自己说"对" | 另一个模型只看"依据能否支撑" |
| 建议形态 | "建议补充实验" | 改哪句 + 怎么验收 + 何时可不改 |
| 责任边界 | 暗示替你审稿 | 只给证据和选项，决定权在你 |

> **一句话记住**：把"我觉得"换成"原文第几行"。

## 第 2 部分｜怎么做：技术上怎么实现？

> **读者问**：技术上怎么实现的？
>
> **一句话回答**：一条五步流水线，外加三个关键设计——**锚点闸门、独立判定、无编造闸门**；锚点决定能不能进清单，独立判定给每条标置信度，无编造闸门管住建议里的数字。

### 2.1 五步流水线

| 步骤 | 输入 | 做什么 | 输出 | 边界 / 失败时 |
|---|---|---|---|---|
| 1. 上传解析 | PDF / LaTeX / DOCX / 文本 | 抽正文、章节、表格、题注；LaTeX 还记节、公式、图表编号的位置 | 结构化文本 | 扫描版或正文不足 500 字 → 提示先 OCR（把图片识别成文字） |
| 2. 提取 | 结构化文本 | 首轮按十类找问题；再用六个方向补漏；最后做主张审计 | 候选问题 + 候选证据 | 某一轮找不到就输出空数组，不凑数 |
| 3. 锚定 | 候选问题 + 原文 | 逐字比对，分 T1 / T2 / T3 | 带锚点的问题 | 找不到依据 → T3，不进清单 |
| 4. 判定 | 主张 + 锚点 | 另一个模型只判"依据能否支撑主张" | 支撑 / 部分 / 不支撑 | 判为"不支撑"的算误报，不计入正向指标 |
| 5. 出清单 | 过闸门的条目 | 排序、补改法四要素、合规提醒（格式 / 匿名化）、图表核对（表内数字 / 题注） | ≤16 条清单 + 台账（每条问题的处理记录） | 名额不够就少出，不拿低质量条目凑数 |

**"六方向"是哪六个？** 与最关键同类工作的对比缺失、统计报告缺失（种子 / 置信区间 / 显著性）、理论假设或定理条件未验证、实验设置细节缺失（数据规模 / 超参 / 评价口径）、符号 / 图表与正文数值不一致、结论外推超出实验覆盖。

**"主张审计"是什么？** 把论文的 5 条主要结论拎出来，逐条问："你的实验或证明，真的支撑这句话吗？"只把**不支撑或不充分**的写成问题。

### 2.2 一张图看全貌

```text
【入口】
门户上传 ／ POST /api/v1/review ／ 本地 /review
        │
        ▼
【解析】正文 + 章节 + 表格 + 题注 + 公式位置
        │
        ▼
【生成：DeepSeek】首轮十类 → 六方向补漏 → 主张审计
        │  候选问题：主张 + 候选证据
        ▼
【闸门 1：锚点】T1 连续 ≥40 字 ／ T2 部分对得上 ／ T3 无依据
        │  只放行 T1、T2
        ▼
【判定：GLM（另一模型，温度 0）】依据能否支撑主张？
        │  支撑 ／ 部分 ／ 不支撑
        ▼
【闸门 2：无编造】建议里的数字必须在原文出现
        │
        ▼
【输出】≤16 条清单 + 改法四要素 + 合规提醒 + 图表核对 + 台账
        │
        ▼
【底座】论文库 594,655 篇 ／ 公开成绩 205,840 条 ／ 会议规范
```

**图 2-1　架构与数据流。** 生成和判定用两个不同厂商的模型；底座只在生成与对照阶段提供检索，不参与"判定"。

### 2.3 三个关键设计

#### 设计一：锚点闸门——没有原文，不算问题

| 等级 | 判定标准 | 是否进清单 | 怎么用 |
|---|---|---|---|
| **T1** | 与原文**连续 ≥40 字**逐字一致（忽略空白和大小写） | 进；高严重度必须是 T1 | 最硬的证据 |
| **T2** | 没有 40 字连续原文，但关键片段能在原文找到（20 字窗口覆盖） | 进，但降权 | 辅助证据 |
| **T3** | 找不到可对应的原文片段 | 不进 | 直接拦掉 |

为什么是 40 字？引用太短，可能在任何论文里"碰巧"出现；40 字连续一致，才基本排除巧合。这是工程折中，不是科学定律——所以 T2 仍然保留，只是降权。

#### 设计二：独立判定——出题人和阅卷人分开

- 生成用 **DeepSeek**，判定用 **GLM**：两个不同厂商的模型，减少"自己给自己打高分"。
- 判定温度设为 **0**：尽量不随机发挥，同一输入尽量得到同一结论。
- 判定模型只回答一个问题：**这段原文，能不能支撑这条主张？** 三档：支撑 / 部分 / 不支撑。
- 它不负责润色，也不建议怎么改——避免"判定"和"生成"混成一件事。

这不是完美方案，但比"生成模型自评"稳。误报率 21.4% 就是在这个协议下测的（见第 3 部分）。

#### 设计三：无编造闸门——数字要出示原件

- 建议里出现的数字（尤其是小数和百分比），必须能在原文找到。
- 找不到：把这个数字从建议里删掉，并记入台账（`fabricated_numbers`），不会悄悄留在报告里。
- 改法还必须满足**四要素**：动作受类别约束、对象锚定、验收可检查、可忽略条件。

| 四要素 | 白话 | 反例 |
|---|---|---|
| 动作受类别约束 | 实验问题就说补什么实验，不能所有问题都"补实验" | 表述问题也让你"补一组消融" |
| 对象锚定 | 改哪一句、哪一段、哪张表 | "建议完善实验部分" |
| 验收可检查 | 怎么算改好，要能核对 | "提升说服力" |
| 可忽略条件 | 什么情况下这条不用改 | 不写，导致作者过度修改 |

### 2.4 五条原则

原文档有七个关键决策；为了好记，归并成五条原则。它们不是口号，每条都对应一个具体设计。第 4 条沿用 v16 的两个习惯：**预注册**（先写下指标、阈值和停止条件，再看结果）、**先量噪声底**（先算清随机波动和人类差异有多大，再谈提升）；口径纪律单独放在 4.3；第 5 条负责把负结果留下来。

| # | 原则 | 白话 | 落到哪个设计 | 如果违背会怎样 |
|---|---|---|---|---|
| 1 | **可核验优先** | 没有原文，就不算问题 | 锚点闸门 T1 / T2 / T3 | 清单变成"AI 的感觉" |
| 2 | **生成与判定分开** | 出题人和阅卷人不能是同一个 | DeepSeek 生成 / GLM 判定，温度 0 | 自己证明自己，误报升高 |
| 3 | **建议必须能落地** | 改哪句、怎么验收、何时不用改 | 改法四要素 + 无编造闸门 | "建议补充实验"式空话 |
| 4 | **先证价值再扩量** | 先在 60 篇上证明有效，再谈全量 | 16 条拐点；4,094 篇暂不跑 | 花大钱买一个没验证的结论 |
| 5 | **负结果照实报** | 没用的方法也写进文档 | 5 角色 −3.33pt 保留 | 只报喜，下次还会踩同一个坑 |

## 第 3 部分｜效果：有数据吗？

> **读者问**：有数据吗？
>
> **一句话回答**：有。60 篇主评测配对比较 **+7.24pt**（95% CI（置信区间）[6.08, 8.48]，52/60 篇胜）；换 120 篇没见过的论文 **+10.17pt**（99 篇变好、0 篇变差）；锚定率 **99%**。负结果也照报。

先解释单位：**pt 是百分点**，不是"增长了 7.24%"。25.6% 比 18.4% 高 7.2 个百分点。

### 3.1 核心指标（60 篇主评测）

| 指标 | 白话定义 | 我们的数 | 容易讲错的地方 |
|---|---|---|---|
| **覆盖率** | 命中的不同人类问题点 ÷ 该篇人类问题点总数（约 38 条/篇） | **25.6%** | 不是"正确率"；分母是人类问题点 |
| **单条命中率** | 我们输出的条数里，有多少条人类也提了 | **57.4%** | "说 10 条，中 5.7 条"最直观 |
| **误报率** | 判定为"依据不支撑"的条目占比 | **21.4%** | 依赖判定协议，应报区间 20–24% |
| **锚定率** | T1 + T2 占全部候选问题的比例 | **99%** | 不是"准确率"；清单内 100% 有锚点，T3 已被拦掉 |
| **定位率** | 能给出章节 / 句子的占比 | **100%** | 定位不等于判断正确 |
| **人类-人类重合** | 一位审稿人的问题被另一位覆盖的比例 | **28.9%** | 用来说明"为什么 25.6% 不算低" |
| **结构上限** | 输出名额 ÷ 人类问题点 | **16 ÷ 38 ≈ 42%** | 上限不等于满分 |
| **候选池上限** | 每篇最多能生成多少条带依据的问题 | **18.8 条/篇** | 这才是覆盖率真正的瓶颈 |
| **bootstrap CI** | 按篇重抽样 1000 次，求均值的区间 | **+7.24pt [6.08, 8.48]** | 不说"p<0.05"，说 CI 和胜负数 |

### 3.2 主对比：A5 vs A0

```text
覆盖率（60 篇，同一批论文上配对比较）
A0 基线    ██████████████████          18.4%   ← 由 25.6 − 7.24 反推
A5 本方法  █████████████████████████   25.6%
           └────────── +7.24pt ─────────┘
           95% CI [6.08, 8.48]；52/60 篇胜
```

**图 3-1　主评测：同一篇论文上各跑一遍，再逐篇比。** 不是拿两批不同论文的平均值比。

**为什么用配对比较？** 论文之间难度差异很大，拿两批不同论文比平均值，容易把"这批更容易"误当成"方法更好"；同一篇上比两个方法，才能抵消论文难度。**为什么报 CI 不报 p 值？** p 值只说"有没有差异"，CI 还说"差异可能有多大"，后者更有用。

### 3.3 独立验证：120 篇 heldout

- **120 篇**没参与调参、与主评测 0 重叠的论文。
- 结果：**+10.17pt**；**99 篇变好、0 篇变差**，其余持平。
- 方向与主评测一致，说明不是"背答案"。

**heldout（留出集）** 就是"换一批没见过的卷子"。如果方法只是记住了这 60 篇的答案，换卷子就会露馅；换卷子还考得好，才说明学到的是可迁移的判断。

### 3.4 负结果（必须主动讲）

负结果不是附录，是方法的一部分。下面这些尝试都真花过时间，结论是"别再用"。

| 尝试 | 结果 | 学到什么 |
|---|---|---|
| 5 角色多智能体 | **−3.33pt** | 同一个模型分角色，会犯同样的错；分工没带来新信息 |
| 按章节遍历召回 | 候选池 +3.0 条/篇，覆盖率 **+0.2pt** | "多想"不等于"想对"；多出来的候选大多过不了闸门 |
| 放宽锚点闸门 | 24.6% → 24.7%（+0.1pt，视为 0 收益） | 瓶颈不在闸门，在候选池只有 18.8 条 |
| 精度过滤（泛化 / 具体性 / 双模型） | 单条命中率没升，F2（综合查准/查全）反降到 53% | "加过滤"不如"换排序"；过滤会误杀真问题 |
| 全量 4,094 篇复跑 | 决定暂不跑 | 先在小样本证明价值，再扩量；不拿算力掩盖方法问题 |

### 3.5 怎么读这些数字

1. **25.6% 不是"只有四分之一正确"**。分母是人类问题点；人类之间也只有 28.9% 的重合——换一位审稿人，也只能覆盖前一位的约三成。把 28.9% 当参照系，25.6% 不算低；但它也不是满分。
2. **42% 是名额上限，不是能力上限**。我们最多输出 16 条，人类平均提 38 条，16÷38≈42%。就算把名额拉到 38，也未必都能找到依据。
3. **真正的瓶颈是候选池 18.8 条/篇**。能带依据的候选只有这么多；所以下一步是提高候选质量，不是把清单拉长。

### 3.6 把效果讲成三句话

1. **我们是做什么的**：把论文里"能用证据核对的问题"，40–80 秒变成一份能照着改的清单。
2. **凭什么可信**：每条都点得回原文（锚定 99%）；建议里的数字必须在原文出现；换 120 篇没见过的论文，结论不变（+10.17pt）。
3. **边界在哪**：需要领域知识的问题（约 51%）要靠知识库补齐，目前标"待确认"；图内数值不读；结论必须人确认。

## 第 4 部分｜数据：论文库和 benchmark 哪来的？

> **读者问**：你的论文库 / benchmark 哪来的？
>
> **一句话回答**：论文库来自公开论文源（arXiv、ACL Anthology、OpenReview、OpenAlex）的聚合，共 **594,655 篇**；benchmark 来自 **Papers with Code 官方导出**（CC-BY-SA），共 **205,840 条成绩**。

### 4.1 论文库：594,655 篇

| 来源 | 数量（约） | 主要用途 |
|---|---|---|
| arXiv | 323,000 | 预印本全文 / 摘要，覆盖 CS / ML 主力 |
| ACL Anthology | 87,000 | NLP 会议论文全文 |
| OpenReview | 55,000 | 7 个会议的投稿、评审、决定 |
| OpenAlex | 3,000 | 补充元数据、引用关系 |
| 其他来源与去重后增量 | 约 12.7 万（差额） | 补缺、合并 |
| **合计** | **594,655** | 检索与同行基线 |

> "K"是约数，合计是精确值；四舍五入后各项相加可能不等于总数。以上为 2026-11 快照，论文库会继续增长；报告里以当次 `call_id` 为准。

### 4.2 benchmark：205,840 条

先解释 **benchmark（基准测试）**：学界约定俗成的评测数据集 / 任务；benchmark 成绩就是某个模型在这个任务上的分数。**Papers with Code** 是一个把论文、代码、榜单成绩对上的公开网站。

| 项目 | 数量 | 说明 |
|---|---|---|
| 成绩记录 | **205,840** | 一条 = 一个模型在一个 benchmark 上的一个成绩 |
| benchmark | **7,432** | 数据集 / 任务 |
| 模型 | **33,176** | 有成绩记录的模型 |
| 覆盖论文 | **15,642** | 其中 **7,274 篇**在论文库 |
| 许可 | **CC-BY-SA** | 官方导出，保留出处；允许转载，但要署名、同许可共享 |

这 205,840 条不是"我们跑了 20 万次实验"，而是**公开成绩的汇总**。它的用途是：当论文声称"我们的模型在某某 benchmark 上更好"时，能对照同任务、同指标下的其他成绩，判断这个"更好"是不是常识、有没有可比对象。

### 4.3 口径纪律：数字必须能回查

AI 系统最容易出的问题，不是"算错"，而是**算法悄悄换了，数字还在**。口径纪律就是把算法钉死，让数字可复算。

| 规则 | 做法 | 防什么 |
|---|---|---|
| **每个数字带 `call_id`** | 报告里的数字能回查到那次调用：模型、时间、输入摘要、输出摘要 | 别人问"57.4% 怎么来的"，你答不出 |
| **`venue` 默认值显式回显** | venue 就是投稿的会议 / 期刊；用户没选时，报告顶部写明"按 NeurIPS 默认口径" | 拿错会议规范，结论跑偏 |
| **口径敏感性 `max_delta_pp`** | 换一种合理口径重算，报告最大变化几个百分点 | 结论只在一种算法下成立 |

`max_delta_pp` 的白话：换分母、换去重方式、换统计窗口，结论最多变几个百分点。变得少，结论就稳；变得多，就必须在报告里说明"这个数依赖口径"。

> **一句话记住**：没有 `call_id` 的数字，不进报告。

## 第 5 部分｜边界：什么做不了？

> **读者问**：什么做不了？
>
> **一句话回答**：只对"文字里能逐字核对"的问题负责；领域知识、图内数值、最终取舍，都不越界。

### 5.1 四条硬边界

| 边界 | 具体表现 | 为什么 | 你该怎么办 |
|---|---|---|---|
| **领域知识型问题（约 51%）** | "这个假设在本领域不成立""缺少关键相关工作" | 需要领域知识库 / 同行共识，文字里没有逐字依据 | 把清单当"待确认"，找导师 / 同行定夺 |
| **图内数值不读** | 折线图、散点图里的数值不提取 | 只读文字、表格、题注；图内数值要视觉读取，容易错 | 自己核对图；表格里的数字我们会核 |
| **结论必须人确认** | 我们给证据和选项，不替你决定改不改 | 研究取舍涉及贡献、时间、风险 | 用"可忽略条件"判断，自己拍板 |
| **中文查询需改写** | 中文能查，但召回不如英文 | 论文库以英文为主，中文要先改写成英文关键词 | 用英文关键词；或让系统改写后再查 |

### 5.2 两条要主动说明的限制

| 限制 | 说明 |
|---|---|
| **没有人工 κ** | κ 是"多人独立标注的一致度"。我们以人类问题点为参照，没有做多人 κ；所以用"人类-人类 28.9%"当参照系，而不是宣称"达到人类水平"。 |
| **扫描版 / 无文本层** | 解析不出 500 字就报错，需要先 OCR（把扫描图片识别成文字）。 |

### 5.3 责任边界

我们负责三件事：

1. 这段原文**在不在**。
2. 这条建议里的数字**有没有原文依据**。
3. 这条依据**能不能支撑**这条主张。

我们不负责：这个研究值不值得做、这个领域是不是已经有人做过、这个结论对工业界有没有用。

> 这条线不是能力问题，是产品定位：作者自查要的是"能改的清单"，不是"另一个权威"。

## 第 6 部分｜怎么用：我怎么用？

> **读者问**：我怎么用？
>
> **一句话回答**：三种用法——网页上传最省事，API（程序调用接口）适合批量，本地部署适合把数据留在自己机器上（模型也要本地化，才真正不出网）。

### 6.1 在线体验

打开 **https://qunzhi.team:8443/portal**（网页入口）：

1. 点"检查一篇论文"。
2. 上传 PDF / LaTeX（也可以直接贴正文）。
3. 选目标会议（不选就按默认口径，报告顶部会写明）。
4. 等 40–80 秒，拿到带锚点的清单。

![图 6-1 门户首页](portal-home-top.png)

**图 6-1　门户首页（2026-11-23 截图）。** 第一屏有上传入口、锚点示例和五条业务线入口。

### 6.2 API：适合批量和集成

网关接口：`POST /api/v1/review`。请求体至少要有 `text`（≥200 字），可选 `title`、`venue`、`max_items`、`mode`、`field`。

```bash
curl -X POST https://qunzhi.team:8443/api/v1/review \
  -H "Content-Type: application/json" \
  -H "Cookie: <你的登录态>" \
  -d '{"title":"My Paper","text":"……正文 ≥200 字……","venue":"neurips","max_items":16}'
```

> 鉴权按你的部署方式带登录态或 Token（调用凭证）；上面的 `Cookie` 只是占位。

返回的是结构化 JSON，含 Markdown 报告和台账（清单、锚点、判定、`call_id`）。

### 6.3 本地部署：数据留在自己机器上

开源包在 `qunzhi-open/`，服务跑在你自己的机器上。注意：生成和判定默认调云端模型，正文会随模型请求发出；要真正不出网，需要把模型换成本地 / 内网服务。

```bash
cd qunzhi-open
pip install -e ".[dev]"
cp .env.example .env      # 填模型 key
make run                  # http://127.0.0.1:8097/docs

# 传 PDF
curl -X POST http://127.0.0.1:8097/upload -F "file=@paper.pdf"
```

本地服务暴露 `/review`、`/upload`、`/review_async`、`/result/{job_id}`，以及 `/docs` 交互文档。

### 6.4 三种用法怎么选

| 方式 | 适合谁 | 怎么做 | 你会得到 | 注意 |
|---|---|---|---|---|
| **在线体验** | 第一次用、单篇自查 | 打开门户 → 上传 → 选会议 → 等 40–80 秒 | 网页报告，可逐条展开锚点 | 需要登录；论文存私有层 |
| **API** | 批量、集成到自己的工作流 | `POST /api/v1/review` | 同结构 JSON + Markdown | 需要登录态 / Token；`text` ≥200 字 |
| **本地部署** | 想把数据留在自己机器、能自己运维 | `pip install` → `make run` | 本地服务 `:8097` | 需要模型 key；模型是否出网取决于配置 |

### 6.5 第一次用的三个建议

1. **先拿一篇已录用 / 已发表的论文试。** 如果清单里出现"明显不存在的问题"，先点开锚点看原文——锚点对不上，就是这条错了，直接跳过。
2. **先改 T1 + 高严重度。** 这类问题证据最硬；T2 只作参考。
3. **先看"可忽略条件"。** 如果条件成立，这条可以不改；别为了"把清单清零"而过度修改。

### 6.6 隐私

在线上传默认进私有存储层：原始文件不落盘，落盘的是脱敏后的正文与哈希；人名只处理标题到摘要之间的前置区，避免误删 Adam、BERT 这类词。**注意：私有层管的是存储与检索，生成 / 判定仍要调模型；论文涉密，建议本地部署并把模型配到内网。**

## 第 7 部分｜术语表：这些词什么意思？

> **读者问**：这些词什么意思？
>
> **一句话回答**：下面 8 个词，用白话记住就能听懂全文；真正要背的只有"锚点"和三个指标的分母。

| 术语 | 白话 | 在本文哪里出现 | 一句话记忆 |
|---|---|---|---|
| **锚点 / T1 / T2 / T3** | 问题对应的那段原文。T1 是连续 ≥40 字逐字一致；T2 是部分对得上（20 字窗口覆盖，降权）；T3 是找不到依据 | 第 0、2 部分 | 没有原文，不算问题 |
| **heldout（留出集）** | 换一批没参与调参、没见过的论文来测 | 第 3 部分 | 换卷子还考得好，才算真会 |
| **配对比较** | 同一篇论文上分别跑 A0 和 A5，再逐篇比差异 | 第 3 部分 | 同题同卷，才比得出高低 |
| **误报** | 我们说有问题，但原文其实不支持 | 第 3 部分 | 冤枉了好人 |
| **单条命中率** | 我们输出的每条里，有多少条人类也提了 | 第 3 部分 | 说 10 条，中 5.7 条 |
| **可忽略条件** | 告诉作者"什么情况下这条不用改" | 第 2、6 部分 | 防过度修改 |
| **无编造闸门** | 建议里的数字必须在原文出现，否则删掉并记录 | 第 2 部分 | 数字要出示原件 |
| **覆盖率** | 人类提的问题里，我们命中多少（按问题点去重） | 第 3 部分 | 该找的 100 个，找到 25.6 个 |

### 7.1 三个最容易混的指标

| 指标 | 分母是谁 | 回答的问题 | 我们的数 |
|---|---|---|---|
| **覆盖率** | 人类问题点总数 | 该找的，找到了多少 | 25.6% |
| **单条命中率** | 我们输出的条数 | 说出去的，有多少被人类认可 | 57.4% |
| **误报率** | 我们输出的条数（经判定） | 说出去的，有多少其实没依据 | 21.4% |

> **一句话记住**：三个数不能互相替代，因为分母不同。看指标先问"分母是谁"。
