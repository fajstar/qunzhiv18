# 隐私保证（详细版）

> 一句话：**你的论文正文永远不会离开你的浏览器**——除非你主动点「深度评审」，把它发给你自己的 LLM 服务商。
>
> 我们只收到：特征名、文献标题、论文 id、关键词。
> 我们收不到：正文、摘要、作者、邮箱。

本文不是口号，而是可执行的验证手册。你可以按第 3 节自己抓包、断网、读源码。

---

## 1. 三种模式的数据边界

| 模式 | 需要 | 发出的数据 | 目的地 | 能力 |
|---|---|---|---|---|
| **纯本地** | 只要浏览器 | 无（0 个业务请求） | — | 20 项规则 + T1/T2/T3 锚定 |
| **本地 + 云端基线** | 网络 | feat / field / refs / pid / q | `qunzhi.team:8443/api/pub/*` | + 同行缺失率 / 漏引候选 / benchmark / 检索 |
| **本地 + 云端 + 自己的 LLM** | LLM key | 正文 + 提示词 | 你填的 LLM 服务商 | + 语义级深度评审（仍逐条锚定） |

模式由页面上的「云端公开统计」开关和 LLM 配置决定。关掉云端 = 纯本地，代码里所有 `fetch` 出口都会提前返回。

---

## 2. 数据清单

### 会离开浏览器的

| 数据 | 何时 | 内容示例 |
|---|---|---|
| 特征名 `feat` | 开云端，查基线 | `"seed"` |
| 领域 `field` | 开云端 | `"cs.LG"` |
| 文献标题 `refs` | 开云端，查漏引 | `["Attention Is All You Need"]`，最多 50 条 |
| 论文 id `pid` | 你主动查 benchmark | `"ax_2611.26510"` |
| 关键词 `q` | 你主动检索 | `"attention"` |
| 正文 | **只在你确认后**，发往你自己的 LLM | 论文全文，最多 60,000 字符 |

### 不会离开浏览器的

- 论文正文、摘要、作者、单位、邮箱、致谢、基金号。
- LLM key：只存本机 `localStorage`（键名 `qz_local_settings_v1`），只放进发往 LLM 服务商的 `Authorization` 头。
- 你的检查结果、锚定引文、导出报告：都在本地生成。

## 3. 自证方法

### 3.1 抓包（2 分钟）

1. Chrome / Edge 打开检查页，按 **F12** → **Network**，勾选 *Preserve log*，点垃圾桶清空。
2. 关掉「云端公开统计」，粘贴正文，点「开始检查」。
   - 预期：只有本目录的 `index.html`、`static/*.css`、`static/*.js`、`config.js`。
   - 预期：**没有** `qunzhi.team`，**没有** LLM 域名。
   - 页面右上角计数应为「本次检查 0 个请求」。
3. 打开「云端公开统计」，再点「开始检查」。
   - 预期：最多两个请求：
     - `POST /api/pub/baseline`，Payload 只有 `{"feat":"...","field":"..."}`
     - `POST /api/pub/missing_cites`，Payload 只有 `{"refs":[...],"field":"...","siblings":30}`
   - 不应出现 `text`、`abstract`、`author`、`email`。
4. 配置自己的 LLM，点「深度评审」，确认弹窗里显示的域名是你填的服务商。
   - 预期：只出现一个发往该域名的 `POST .../chat/completions`。
   - 预期：`qunzhi.team` 没有收到任何带正文的请求。
   - 点开 Request Payload，能看到正文——它只在这一个请求里。

### 3.2 断网

1. 关闭 Wi-Fi / 拔网线。
2. 刷新页面，点「载入示例」→「开始检查」。
3. 预期：20 项规则、T1/T2 锚定、问题清单照常输出；只有云端卡片显示「云端不可达」，本地结果不受影响。

### 3.3 读源码

整个包是纯静态、无构建、无压缩、无 CDN。重点看三个文件：

```text
static/rules.js    20 项规则的正则与解释
static/anchor.js   T1/T2/T3 锚定、References 解析
static/qz.js       全部交互与网络请求
```

在 `static/qz.js` 里搜索 `fetch(`，只会看到三处：

1. `cloudCall()`：拼 `base_url + /api/pub/...`，body 由调用方传入，只有 feat/field/refs/pid/q。
2. `runLLM()`：拼 `chatUrl(llm.base_url)`，body 含正文，header 是你自己的 key。
3. `testLLM()`：只发一句 "只回复 ok"，不发正文。

`config.js` 在 `file://` 下**不会**请求 `config.json`（浏览器也不允许）；在 http(s) 下也只在地址带 `?config=1` 时才读，所以默认连配置文件请求都没有。

### 3.4 看服务端字段白名单

云端接口源码 `app/pub_api.py`（在服务端仓库，不在本包）对请求体做硬白名单：

```python
BANNED_KEYS = {"text", "fulltext", "content", "abstract", "author",
               "authors", "email", "affiliation", ...}
```

出现即 HTTP 400，并在响应里写明被拒字段。你可以直接试：

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  https://qunzhi.team:8443/api/pub/baseline \
  -H 'Content-Type: application/json' \
  -d '{"feat":"seed","text":"正文不应上传"}'
# 400
```

## 4. 服务端能看到什么

即使请求体里没有正文，HTTP 请求本身仍会暴露一些元数据。我们如实列出：

| 服务端可见 | 说明 |
|---|---|
| IP、时间、URL、状态码、User-Agent | 任何 Web 服务都会记录，用于运维与防滥用 |
| feat / field / refs / pid / q | 请求体内容，全部是公开或统计信息 |
| 请求体大小 | 只有几十到几千字节；正文不会出现在这里 |

服务端**不可见**：正文、摘要、作者、邮箱、LLM key、你的检查结果。

## 5. 边界与风险（不粉饰）

1. **LLM 是例外**：你确认后，正文会发给你配置的服务商。它是否留存、是否用于训练，取决于它的条款。不想发就别开 LLM。
2. **浏览器扩展**：能读页面 DOM 的扩展理论上能看到文本框。请用干净配置，或开无痕窗口。
3. **HTTPS 证书**：云端走 HTTPS，证书由部署方维护。出现证书警告时先核对再继续。
4. **CORS**：部分 LLM 服务商不允许浏览器直连，会失败。我们不会替你转发；可换服务商或用本地 Ollama。
5. **正则不是语义理解**：规则只能发现「文中是否出现相关表述」，不能判断实验做得对不对。未检出 ≠ 一定没做；命中 ≠ 一定做对。
6. **锚定 T1 只证明引文存在**：不证明解读正确。所有结论必须由人确认。
7. **没有「绝对安全」**：任何软件都不能承诺。我们能承诺的是可验证：开源、白名单、抓包、断网测试。

## 6. 常见问题

**Q：双击打开时，为什么设置里的 LLM key 刷新就没了？**
A：如果没勾「记住 key」，key 只存在内存；勾了才写 localStorage。公共电脑上建议不勾，用完点「清除 key」。

**Q：config.json 里的 key 安全吗？**
A：它只在你本机；`.gitignore` 已忽略 `config.json`。不要提交、不要发群里。更推荐在页面设置里填，存 localStorage。

**Q：云端统计的数据源是什么？**
A：公开论文库的聚合统计（L1/L2 论文的特征分布、公开文献引用关系、公开 benchmark 数字）。不返回全文、摘要、作者。

**Q：为什么漏引查询要传文献标题？标题不是隐私吗？**
A：已发表论文的标题是公开信息，且接口只拿它做「共同引用」匹配，不返回任何与你论文相关的内容。你仍然可以选择不传（关云端）。

**Q：报告会上传吗？**
A：不会。报告由浏览器生成 Blob 并直接下载，没有上传接口。
