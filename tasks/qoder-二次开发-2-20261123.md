# Qoder 二次开发任务（第 2 轮）：补 requirements.txt + CI

## 背景

README 的「快速开始」写着 `pip install -r requirements.txt`，但**仓库里没有这个文件**（也没有 pyproject/setup.py）。
任何人克隆下来都装不了依赖 —— 这是"看起来能跑、实际跑不起来"的硬伤。

## 硬约束（违反即失败）

1. **不要修改 `main_gateway.py` 的任何内容**（一个字节都不行）；
2. 不要动 `static/`、`templates/`、`tests/` 里已有的测试；
3. 不要新增第三方依赖（只允许把**代码里已经在用**的依赖写进清单）；
4. 只允许：新增 `requirements.txt`、新增 `.github/workflows/test.yml`、修改 `README.md` 的安装/测试两节。

## 任务 A：生成 requirements.txt

1. 扫描仓库所有 `.py` 文件（含 `rag/`、`review_plugins/`、`source_plugins/`、子目录）的 import；
2. 只保留**第三方顶层包**，排除：Python 标准库、以及仓库内的本地模块（如 `citations`、`guard`、`review_anchors`、`complexity`、`input_intent`、`privacy_scrubber`、`local_store`、`presets`、`feedback`、`cnki_search`、`rag.*` 等）；
3. 已知需要（供核对）：`fastapi`、`uvicorn`、`httpx`、`pydantic`、`starlette`、`requests`、`PyMuPDF`（import 名是 `fitz`）；
4. 版本用**下界约束**（如 `fastapi>=0.110`），不要锁死精确版本；
5. 文件头加一行注释说明用途。

## 任务 B：加 CI

新建 `.github/workflows/test.yml`：

- 触发：`push` 到 `master` + 所有 `pull_request`；
- 环境：`ubuntu-latest`，Python `3.11`；
- 步骤：checkout → setup-python（带 pip 缓存）→ `pip install -r requirements.txt` → `pip install pytest` → `python -m pytest -q tests`；
- 工作目录就是仓库根（测试直接 `import complexity` 这种同级导入）。

## 任务 C：README 对齐

把「快速开始 → 装依赖」改成两步：

```bash
# 1. 建虚拟环境（可选但推荐）
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate

# 2. 装依赖
pip install -r requirements.txt
```

并在「开发与测试」一节补一句：CI 会在每次 push 时跑 `pytest -q tests`（见 `.github/workflows/test.yml`）。

## 验收（我会自己跑）

1. `python -m pytest -q tests` 仍全绿（65 条）；
2. `requirements.txt` 里包含扫描到的全部第三方包（`fitz` 要写成 `PyMuPDF`）；
3. `.github/workflows/test.yml` 是合法 YAML 且包含 `pytest -q tests`；
4. `git diff main_gateway.py` 为空。
