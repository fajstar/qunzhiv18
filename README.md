# 群智 local · 可核验的论文自查（本地版）

> 把一篇论文变成一份「每条都能点回原文」的问题清单。
> **你的论文永不上传。**

群智 local 是一个纯静态的单页工具：20 项可复现性 / 统计严谨性 / 评审透明检查，全部在浏览器本地跑；每条命中都锚回原文，标 **T1 / T2 / T3**，找不到出处的说法直接拦掉。可选连接 5 个零隐私公开接口（同行基线、漏引候选、benchmark、检索、版本），以及你自己的 LLM（浏览器直连，key 是你自己的）。

- 零构建：没有 npm、没有 webpack、没有后端。
- 零上传：规则与锚定是纯 JS；正文只在你主动开 LLM 时才发给你自己的服务商。
- 零锁定：MIT，代码可读、可 fork、可离线保存。

> **后续优化承诺（写在最显眼的位置）**
>
> 我们会持续迭代，并且**每个版本都如实更新本 README 的 changelog 与能力边界**：
> 不静默加遥测、不把「未检出」说成「论文有问题」、不把正则命中说成「做对了」、不在不通知的情况下改变隐私口径。
> 路线图见下文；能力做不到的，我们会明确写「不做」。

## 3 分钟上手

### 方式 A：双击打开（纯本地，推荐先试）

1. 下载本目录（`git clone` 或解压 zip）。
2. 双击 `index.html`。
3. 粘贴论文正文 → 点「开始检查」。
4. 想试示例：点「载入示例」→「开始检查」。

纯本地模式**不需要网络、不需要 key**。规则、锚定、导出报告都能用。

### 方式 B：本地静态服务器（要用 config.json 时）

浏览器不允许 `file://` 页面读取同目录 JSON，所以想用 `config.json` 时：

```bash
cd qunzhi-local
cp config.example.json config.json     # 可选：填自己的 LLM key
python -m http.server 8000
# 打开 http://localhost:8000/?config=1   ← 加 ?config=1 才会读 config.json
```

> 为什么默认不读 config.json？为了避免你没放这个文件时，浏览器控制台出现一条 404。
> 页面「设置」里保存的配置优先级高于 config.json。

也可以不用 config.json：直接在页面「设置」里填，存在本机 localStorage（更推荐，key 不会落到文件里）。

### 可选：接云端公开统计

默认已开启 `https://qunzhi.team:8443/api/pub`。关掉「云端公开统计」开关即完全离线。接口字段与 curl 示例见 [`docs/API.md`](docs/API.md)。

### 可选：接你自己的 LLM

1. 页面右上角「设置」→ 填 Base URL / 模型 / API key。
2. 保存后点「深度评审」，确认弹窗里显示的是**你配置的服务商域名**。
3. 正文只发往那一家；`qunzhi.team` 不会收到正文。

> 浏览器直连可能被服务商的 CORS 策略拦截。被拦时请换支持浏览器直连的服务商，或使用本地 Ollama（`http://localhost:11434/v1`）。本工具**不会**替你转发。

## 三种模式

| 模式 | 需要 | 隐私 | 能力 |
|---|---|---|---|
| **纯本地** | 只要浏览器 | ✅ 最好：0 个业务请求 | 20 项规则 + T1/T2/T3 锚定 + 导出报告 |
| **本地 + 云端基线** | + 网络 | ✅ 好：只发 feat/field/refs/pid/q | + 同行缺失率 / 漏引候选 / benchmark / 公开检索 |
| **本地 + 云端 + 自己的 LLM** | + LLM key | ✅ 好：正文只给你选的服务商 | 完整能力：语义级深度评审（仍逐条锚定） |

模式由页面开关决定，随时可切。关掉云端后，所有云端按钮会提前返回，不发出请求。

## 隐私承诺

- 规则检查：纯 JS 在本地跑。
- 深度评审：你的浏览器**直连** LLM 服务商，key 是你自己的。
- 我们只收到：**特征名、文献标题、论文 id、关键词**。
- 我们收不到：**正文、摘要、作者、邮箱**。
- 云端接口对禁止字段是硬拒绝（HTTP 400），不是「忽略」。
- 页面右上角有「本次检查 N 个请求」计数器；设置里有请求列表（只记 URL / 方法 / 状态码）。

### 自己验证（2 分钟）

1. F12 → Network，清空记录。
2. 关掉云端，粘贴正文，点检查：应当只有本目录的静态资源，0 个 `qunzhi.team` 请求。
3. 打开云端，再检查：只应出现 `/api/pub/baseline` 与 `/api/pub/missing_cites`，Payload 里只有 feat/field/refs。
4. 断网刷新，点「载入示例」：本地规则照常出结果。
5. 开 LLM 后：只出现一个发往你配置域名的请求，正文只在该请求里。

详细步骤、请求样例、风险边界见 **[privacy.html](privacy.html)** 与 **[docs/隐私保证.md](docs/隐私保证.md)**。

## 我们提供什么 API

5 个零隐私公开接口，免 key、限流、只返回统计/公开数据：

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/pub/baseline` | POST | 特征 × 领域的同行缺失率（只回统计） |
| `/api/pub/missing_cites` | POST | 传文献标题，返回「同领域兄弟都引了、你可能漏了」的候选 |
| `/api/pub/benchmark?pid=` | GET | 公开论文的 benchmark 分数 |
| `/api/pub/search?q=&limit=` | GET | 公开库关键词检索（标题/年份/领域/pid） |
| `/api/pub/version` | GET | 版本、快照、库规模、数据截止日 |

完整字段、curl、返回样例、错误码、限流见 [`docs/API.md`](docs/API.md)。

只接受：`feat` / `field` / `refs` / `pid` / `q`。
绝不接受：`text` / `abstract` / `author` / `email`。

## 我们不做什么

- **不读图**：图表、公式截图、实验照片不在能力范围内。
- **不做数学推导**：不验证定理证明、不推导公式。
- **不做语法润色**：不替代写作助手。
- **不替代同行评审**：输出是问题清单，不是录用决定，也不给论文打分。
- **不保证「未检出 = 没做」**：正则只找表述线索；命中也不等于做对。**结论必须由人确认。**
- **不替你转发 LLM 请求**：浏览器直连，我们不碰你的正文和 key。

## 已知边界

- 只接受**文本**输入；PDF 请先复制正文。扫描版 PDF 需要 OCR。
- 规则是正则，不是语义模型；缩写、同义表述、非英文论文可能漏检。
- 锚定要求逐字命中；改写过的引文会降为 T2 或被 T3 拦掉。
- References 标题提取是启发式，界面里可手动修正；标题不全时漏引候选会变少。
- benchmark 只覆盖公开表里有记录的论文；`paper: null` 是公开快照口径差异，不是查询失败。
- 云端需要能访问 `qunzhi.team:8443` 且证书受信；离线时请关云端。
- LLM 直连受服务商 CORS 限制；被拦时本工具不会代转。
